# 自适应投放的预算与退群边界

- 试投 30 条与成熟投放分别计数；实际失败的广告不占成功投放额度，但仍保留账号发送间隔。未知结果继续等待原记录对账。
- 正常账号总读预算仍为 120/分钟、240/小时、2400/日。普通任务最多使用共享窗口的 75%；剩余空间留给广告校验、存活回查、结果与退出核对。冷却及动态降载仍作用于所有任务。
- 更新同步另外受 60/小时、600/日限制，搜索和预审仍受后台上限限制。所有分类仍消耗同一总预算，不能相加理解为额外额度。实际参数按账号降载系数缩小。
- 短任务连接不订阅实时更新；长期监听保留订阅。监听更新循环在发起 RPC 前遇到预算或冷却等待时可取消地等待，每次唤醒重新检查；业务调用仍返回明确延期，不重发未知消息。
- RPC 统计保存方法与受控业务用途，不保存消息、请求参数或凭据。
- 永久、剩余超过三天、或连续有效观察超过三天的文字禁言，在最终退群前再次核验实时权限。解除、缩短或证据不足时不能继续按旧事件退群。
- 撤销禁言退出使用追加事件保留历史，只撤销对应账号本次成员关系的证据。重新进入资格审核前不恢复广告。其他账号证据及最低频率删帖退出条件保留。
- Telegram 的 `ChannelParticipantBanned` 也表示仍在群内的禁言成员；使用离群标记和查看权限区分禁言与被踢出。

相关回归入口：`test_adaptive_review_regressions.py`、`test_rpc_listener_priority.py`、`test_three_day_send_restriction.py`，以及原资格审核、退出保护、账号预算和并发测试。

删帖事件回查的 PostgreSQL 行锁限定于广告记录表；关联群和广告配置的外连接不参与行锁，避免事件处理在生产数据库中报错。
