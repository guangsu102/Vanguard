# Vanguard 稳定运行修复：验收与发布记录

目标：让监听接收、本地事件处理、广告和加群工作在预算紧张、断线与重启后能够自动恢复；不将本地读取限额误报为 Telegram 封禁。

## 修复

1. 在原 15% 生存安全池内保留窗口总量 2%、至少 3 次的监听恢复额度。用于 SDK 授权/状态恢复必需读取；历史补读仍使用原同步池。普通生存检查和审核借用均不能侵占这部分。总额度、广告份额、实际消耗和原到期时间保留。
2. SDK 控制读取遇到本地额度等待时保留连接与持久化入口；真实 Telegram 冷却仍按原规则处理，不伪造游标或 RPC 回复。
3. 本地投影事实及 PostgreSQL 事件消费按启用账号运行，不再以已经连接的监听列表作为前提。SQLite 确认在数据库提交之后，使用精确版本比较，避免并发新事实被旧确认删除。
4. 明确删除回调按账号、群命名空间和成功消息回执直接处理，重复事件只改变状态一次；旧周期/重新入群事件不惩罚新周期。回调遗漏或状态未知仍由周期检查兜底。
5. 已有自适应试投调整为下一周期检查，减少 2 分钟/1 小时重复读取；未知外部结果保持对账，保护群和退出授权仍生效。
6. 新鲜、未失效且资料/策略一致的 AI 待审证据可本地继续，不因 Telegram 读取额度阻塞；需要新证据的审核只延期自身。审核和预审可借用经过到期工作预测后确认为闲置的安全池额度，借用按原窗口记账。
7. 预算快照区分原始消耗与旧窗口未分类用量的保守归属，避免把归属后的同步/加群数字误认为实际新增调用。
