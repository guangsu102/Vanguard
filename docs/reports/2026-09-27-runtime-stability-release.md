## 部署中发现并修复的前端问题

最初的前端候选继承了 Windows 打包目录的 0700 权限。首页返回 200、Nginx 配置检查通过，但 Nginx 无权读取 assets 目录，入口脚本返回 404；最初隔离验收只检查首页，未覆盖真实资源读取，因此未提前捕获。

发现后仅将前端恢复到上一版，确认所有入口资源 HTTP 200；后端继续运行新版本。修正版镜像显式固定静态目录为 0755、文件为 0644。由于旧资源 404 已被 CDN 缓存，使用相同源码重新构建带 `-s1` 文件名的整套资源，未修改 DNS、Cloudflare 配置或业务逻辑。先在隔离容器验证全部 116 个资源内容，再仅切换前端，最后完成全部公网资源哈希核对。前端资源读取已恢复。

后续同类发布应保留完整资源 HTTP/哈希验收，不能只依赖首页 200 和 `nginx -t`。权限修复的 Dockerfile、manifest 和发布脚本均保留在本次制品目录中。
