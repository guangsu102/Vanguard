# 账号异常分类与有限自动恢复

## 实现

明确的网络、代理连接及连接超时故障首次进入 ERROR 时，在独立短事务中同时写入固定原因、错误时间代次和审计事件。重复落库不改错误代次；旧连接失败不能覆盖操作员的新变更。普通 SDK 连接重试由 10 次改为 0，统一交给恢复调度。

只有启用账号且启用运营配置的推广账号可自动恢复。首次等待 60 秒，后续失败分别等待 300、900 秒；每个错误周期最多进行 3 次受控核验。次数在网络操作前原子保存，进程重启、取消或写回失败不退回已使用次数。预算、冷却、租约和代理预检等待使用实际到期时间（至少 5 分钟），最多 48 次等待、24 小时一个周期。达到上限转人工。

会话冲突保留原有磁盘和 Redis 隔离保护，只能通过身份核验后恢复。授权失效、身份不符、封禁、冻结、未知原因、缺少可信来源或过期错误记录不会自动上线。较新的人工核验硬失败也会阻止旧故障继续触发。已有历史 ERROR 不通过猜测原因自动解封。

手动和自动核验共用账号互斥锁，核验前后检查凭证、代理、账号状态、运营开关和错误代次；停止账号能阻止进行中的恢复提交 ONLINE。网络等待期间归还数据库连接，核验期间不持整个账号池的锁。恢复只核对现有会话身份，不发送营销消息或执行加群；读取继续受原预算控制。

断开过程正确等待 SDK 返回的 Future，等待最多 10 秒。底层关闭 Future 不因等待超时或调用取消而被取消，其最终异常会被消费。无法确认连接已关闭时保留 client、guard 和可续期 owner，维持隔离，不宣告恢复成功。

Redis 每个受影响账号使用一个不超过 1024 字节的固定状态键，不按尝试创建新键；自动任务锁和核验锁有时限。状态损坏或不可读取时暂停自动恢复。正常账号不新增 Telegram 读取；仅有 ERROR 候选时批量读取故障审计。

前端 ERROR 账号提供“核验恢复”。停用保存 is_active=false，并保留 ERROR、BANNED、RESTRICTED 和隔离状态。连接请求不再伪造实际连接时间或次数；界面使用服务端返回状态和中文固定原因。
