# 广告优先优化收尾

目标：`oracle4c24g:/opt/vanguard`，后端 `127.0.0.1:18080`、前端 `127.0.0.1:13000`。北京时间 2026-09-29。用户已授权修复和部署，本轮仅涉及 Vanguard。

## 根因与改动

1. 监听存在原始积压时，旧追赶节奏仍为每个同步 RPC 约 43 秒。服务端连续返回 `DifferenceSlice`，等待期间又有新更新到达，导致持续追不上。本轮将持久积压或未完成切片的平滑间隔缩短为 1 秒；分钟、小时、日累计上限、广告 35% / 存活 15% 保底及 Telegram 冷却继续执行。完成切片后恢复普通节奏，未重置任何读取计数器。
2. 候选预览与群资料刷新共用后台读取额度。00:34 后台窗口已用完 25/25，而总窗口仅用 40/168；当日读取计数显示 20 次群资料刷新启动，每次还包括登录状态等开销，候选预览没有推进。本轮将候选预览归入关键业务读取通道；有独立试投补充缺口时，资料刷新让出资源。面板等待时间使用同一通道口径。
3. 候选预览保存的旧预算重试时间可能晚于当前可用时间。现在重新核对实时读取门槛，不因旧时间单独阻塞；真实平台冷却仍阻挡执行，旧候选证据的有效期不会延长。
4. 新增同步切片进度摘要，仅保存游标、时间和计数，不记录聊天正文或凭据。

同步仍由 SDK 按更新序列完成，没有伪造返回结果或强行跳过游标。协议依据：[Telegram 更新顺序](https://core.telegram.org/api/updates)、[getDifference](https://core.telegram.org/method/updates.getDifference)。
