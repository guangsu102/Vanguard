# 单群广告动态频率本地验收

日期：2026-09-26。范围：本地代码、迁移、测试、容量展示。未部署，未改生产开关，未执行真实 Telegram 发送或退群。

## 行为

- 每账号滚动 24 小时最多新增 30 条试投广告；成熟投放独立记账，继续受账号发送节奏、风险和读取预算约束。
- 每群初始 1 条；同一档位 3 条不同广告分别完成 2 分钟、1 小时、24 小时存活核验，且档位至少运行 24 小时，才升一档：1 / 2 / 3 / 5 / 8 / 12 / 18 / 24 / 30。群配额跨账号、跨活动共享。
- 成熟广告也执行三个检查点。前条未通过 2 分钟、已有到期检查未完成、结果未知或存在在途发送时，该群暂停续发。
- 确认删除后减半向下取整、最低 1，暂停至少 24 小时，72 小时内不升档。相同发送版本的批量删除只处罚一次；旧高频消息的迟到删除不冒充低频失败。
- 在当前 1 条档实际发送的新广告仍被确认删除，或确认该账号被群禁言，持久化退群意图。受冷却限制时先禁发、等可执行后退群；退出结果未知先核实成员身份。所有账号禁发该群，阻止自动重加。
- 删除通知仅触发核实；两次独立成功读取间隔至少 120 秒，确认消息缺失、账号仍为成员、群可读且无自动过期可能后，才判定删除。限流、断网、读取失败不当作删除。
- 明确群规限制优先；受保护、自建、管理员身份群保留原有退群保护。

## 代码与开关

核心：`backend/app/modules/acquisition/adaptive_frequency.py`。接入现有广告预留、账号持久化预算、发送前复核、存活检查、退出与重加入门禁，以及容量面板。

新增 Alembic `047_adaptive_group_frequency`（父版本 `046_dynamic_growth_capacity`），对应 SQL `062_add_adaptive_group_frequency.sql`，新增共享群状态及幂等事件表。`adaptive_ads_enabled` 默认 false，只有它和 `dynamic_capacity_enabled` 同时开启才使用新预算。当前机制面向现有 dynamic 资格投放流程；资格总开关、账号范围及广告许可仍需有效。

通过现有账号操作配置 API 读取/修改 `adaptive_ads_enabled`。启用前要核对退出总开关及账号/成员范围；若配置了退出原因白名单，必须显式纳入 `frequency_muted` 与 `frequency_deleted_at_minimum`，否则保持禁发等待而不会越权退群。

- 12 个后端相关测试文件：276 项通过；包含原有广告派发、资格审核、Telegram worker、退出范围、账号预算，以及 25 项新增机制测试。

- 前端 `npm run build:check` 通过（含 TypeScript 检查）；构建仅有已有的大包尺寸提示。
- 新核心、迁移及测试文件通过 Ruff，相关 Python 文件可编译。运行日志及源码指纹位于 `deploy-artifacts/adaptive-frequency-local-20260926/`。

测试使用隔离 SQLite 和模拟 Telegram/RPC，验证账本、检查驱动、预留失效和退出对账；不等同于 PostgreSQL 实际并发压测或真实 Telegram E2E。当前机器没有 Docker，尚未对实际 PostgreSQL 执行新增迁移。超过 24 小时的删除依赖收到且能归属群的删除事件重新核实，没有承诺对所有历史广告无限轮询。
